# SDS-07: Data Model

## Where everything lives

| What | Storage | Why |
|------|---------|-----|
| Users, sessions, messages | Postgres (Neon) | Structured, relational, need to query |
| Paper metadata (title, authors, DOI, year) | Postgres (Neon) | Structured, need to query and filter |
| Paper + document embeddings (vectors) | Postgres (Neon) via pgvector | Same DB, no extra service |
| Paper chunk offsets + embeddings | Postgres (Neon) | Chunk text stays in R2; only offsets + vectors in Neon |
| Usage events (cost tracking) | Postgres (Neon) | Need to aggregate per user per month |
| LangGraph checkpoint data | Postgres (Neon) | Auto-created by AsyncPostgresSaver |
| User memory | Postgres (Neon) | Small text field on users table, read every session |
| Active session state during a live run | Redis (Upstash) | Temporary, fast, TTL'd |
| Per-run visited paper IDs (dedup) | Redis (Upstash) | Temporary set, gone when run ends |
| Rate limit counters | Redis (Upstash) | Temporary, fast increment |
| Paper full text + user document content | R2 (Cloudflare) | Large text blobs; chunk text sliced from here at query time |
| User-uploaded files (PDF, text) | R2 (Cloudflare) | Binary files, large |
| JSONL session archives | R2 (Cloudflare) | Written at session end as human-readable export |
| LLM call logs (prompts + responses) | LangFuse (hosted) | External service, browsed not queried |
| Application errors | Sentry (hosted) | External service |
| Application logs | Render log stream | 7-day window, not stored by us |

**Key design decisions:**
- Redis no longer buffers messages. Messages are written directly to Postgres from inside LangGraph nodes.
- Chunk text is not stored in Neon. Only `(char_start, char_end)` offsets into R2 are stored. RAG query fetches top-K chunk metadata from Neon, then fetches the actual text from R2. Saves ~45 MB at 15K chunks — significant given Neon's 0.5 GB limit.
- `papers` and `paper_chunks` are global (shared across users). User ownership is tracked via `user_papers`. RAG queries always filter through `user_papers` — no user ever queries chunks they don't own.
- `user_documents` and `document_chunks` are fully user-scoped. No global dedup.

## LangGraph checkpoint tables

`AsyncPostgresSaver.setup()` auto-creates these. Never queried directly from application code.

| Table | Purpose |
|-------|---------|
| `checkpoints` | One row per graph step. `thread_id TEXT`, `checkpoint_id TEXT`, `checkpoint JSONB` |
| `checkpoint_blobs` | Channel data as `BYTEA` — serialised Python, not queryable as text |
| `checkpoint_writes` | Intermediate writes per task, also `BYTEA` |
| `checkpoint_migrations` | Internal version tracking |

`thread_id` = our `session_id`. We pass `{"configurable": {"thread_id": session_id, "run_id": run_id}}` at every graph invocation. Checkpoints are short-lived scratchpads — clean up entries older than 7 days. Cross-turn memory is reconstructed from our `messages` table, not from checkpoints. No FK to these tables — they get periodically deleted. Manual cross-reference is possible via `checkpoint_id` stored on `messages` rows.

## Schema

### `users`

One row per person. `id` is the Clerk user ID — we never generate our own.

Note: `memory TEXT` was removed. Long-term memory is now managed by LangMem via `AsyncPostgresStore`, which creates its own tables namespaced per user. See SDS-10.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `id` | `str` | PK | Clerk user ID (`user_2abc...`) — not generated by us |
| `email` | `str` | | Copied from Clerk at first login, never updated |
| `created_at` | `datetime64[ns, UTC]` | | |
| `updated_at` | `datetime64[ns, UTC]` | | Needs a Postgres `ON UPDATE` trigger |

### `sessions`

One row per conversation thread. All content in this system is per-user — users see entirely different sessions, papers, documents, and messages. Branching: when a user edits a message, the app creates a new session with `parent_session_id` and `branch_from_message_id` set. The new session's `load_context` node reconstructs history from our `messages` table up to `branch_from_message_id` — no LangGraph checkpoint copy needed.

`mode` is immutable after creation.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `id` | `str` | PK | UUID we generate — also used as LangGraph `thread_id` |
| `user_id` | `str` | FK → `users.id` | |
| `title` | `str` | | Generated by LLM after first exchange, null until then |
| `mode` | `str` | ENUM(`quick`, `deep`) | Immutable after creation |
| `parent_session_id` | `str` | FK → `sessions.id`, nullable | null for root sessions |
| `branch_from_message_id` | `str` | FK → `messages.id`, nullable | Message the branch diverged from |
| `created_at` | `datetime64[ns, UTC]` | | |
| `updated_at` | `datetime64[ns, UTC]` | | |

`parent_session_id` and `branch_from_message_id` are always set together or both null — enforced in application code.

### `runs`

One row per graph invocation. A session has many runs — one per user turn. `id` is generated by us and passed into the graph via `config["configurable"]["run_id"]` and into LangFuse as metadata — every LLM call and tool call in LangFuse traces back to a row here.

On failure, `status = 'failed'`. Frontend renders error state + retry button when `run.status = failed` and no assistant message exists for that run.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `id` | `str` | PK | UUID we generate — passed into graph config and LangFuse metadata |
| `user_id` | `str` | FK → `users.id` | Denormalised for direct user-scoped queries |
| `session_id` | `str` | FK → `sessions.id` | |
| `status` | `str` | ENUM(`running`, `complete`, `failed`) | |
| `created_at` | `datetime64[ns, UTC]` | | |
| `updated_at` | `datetime64[ns, UTC]` | | |

### `messages`

Written from inside LangGraph nodes as they complete — not buffered. User message written at graph entry. Thinking rows written inside thinking/planning nodes. Assistant row written inside output node. Failed runs leave no orphaned partial rows — if a node didn't complete, its message row doesn't exist.

In DEEP mode, parallel researchers produce concurrent thinking rows identified by `node`. Frontend groups all thinking rows for a run together rather than forcing false linear ordering.

Node retries are idempotent — upsert on `(session_id, run_id, role, node)`. Retried node overwrites previous attempt.

`checkpoint_id` stored for debug cross-reference to LangGraph state — no FK constraint since checkpoints are periodically deleted.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `id` | `str` | PK | UUID we generate |
| `user_id` | `str` | FK → `users.id` | Denormalised |
| `session_id` | `str` | FK → `sessions.id` | |
| `run_id` | `str` | FK → `runs.id` | |
| `checkpoint_id` | `str` | nullable | LangGraph `checkpoint_id` at write time — no FK constraint |
| `role` | `str` | ENUM(`user`, `assistant`, `thinking`) | |
| `node` | `str` | nullable | Graph node that wrote this row — required for thinking rows in DEEP mode |
| `content` | `str` | | Complete text — no partial rows |
| `sequence_number` | `Int64` | | Ordering within a single node's output |
| `created_at` | `datetime64[ns, UTC]` | | |

UNIQUE constraint on `(session_id, run_id, role, node)`.

### `paper_chunks`

Global. One row per chunk of a paper's full text. Text is not stored here — only offsets into the R2 file at `papers.r2_key`. RAG query: ANN search returns top-K rows → group by `r2_key` → fetch from R2 → slice `content[char_start:char_end]`. User scoping in RAG: `WHERE paper_id IN (SELECT paper_id FROM user_papers WHERE user_id = X)`.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `id` | `str` | PK | UUID |
| `paper_id` | `str` | FK → `papers.id` | |
| `chunk_index` | `Int64` | | Position within document |
| `char_start` | `Int64` | | Start offset in R2 full text |
| `char_end` | `Int64` | | End offset in R2 full text |
| `content_embedding` | `object` | | `vector(1536)` — query-to-chunk semantic search |
| `specter_embedding` | `object` | | `vector(768)` — paper-level similarity, nullable |
| `created_at` | `datetime64[ns, UTC]` | | |

### `user_papers`

Ownership junction. When a paper enters a user's library (via agent search, citation snowball, upload, or explicit save), a row is inserted here. All RAG queries and paper list views filter through this table. Two users can own the same paper — the global `papers` row is shared, their `user_papers` rows are independent.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `user_id` | `str` | PK (composite), FK → `users.id` | |
| `paper_id` | `str` | PK (composite), FK → `papers.id` | |
| `source` | `str` | ENUM(`agent_search`, `citation_snowball`, `user_upload`, `doi_bridge`) | How it entered the library |
| `added_at` | `datetime64[ns, UTC]` | | |

Composite PK on `(user_id, paper_id)`.

### `user_documents`

Non-paper content per user. Covers saved web pages, blog posts, GitHub pages, uploaded plain text, uploaded PDFs that aren't formal papers. Fully user-scoped — no global dedup.

**V1 supported formats:** PDF, plain text, markdown.
**V2:** images (multimodal model needed), PPT, DOCX (LibreOffice/python-pptx conversion).

Web search results are NOT automatically indexed. The LLM makes an explicit judgement call during a run — if a web source is substantive enough to be worth indexing, it flags it and the node creates a `user_documents` row. Otherwise web results remain context-only ([W1],[W2] citations).

## R2 structure

Bucket name: `delta-sessions`

```
delta-sessions/
│
├── papers/
│   ├── {paper_id}.txt              # extracted full text (global, shared across users)
│   └── {paper_id}.pdf              # cached original PDF (global)
│                                   # sourced only from legal open access:
│                                   # arXiv, Unpaywall, CORE
│                                   # personal non-commercial use, not redistributed
│                                   # overwritten if re-fetched (no versioning in v1)
│
├── uploads/
│   └── {user_id}/
│       └── {document_id}/
│           └── original.{ext}      # raw file as uploaded (pdf | txt | md)
│                                   # preserved so re-extraction is possible
│                                   # without user re-uploading
│
├── documents/
│   └── {user_id}/
│       └── {document_id}.txt       # clean extracted text
│                                   # covers both uploads and saved web pages
│
├── web/
│   └── {user_id}/
│       └── {document_id}.html      # raw HTML snapshot of saved web page
│                                   # not created for GitHub (already clean text)
│                                   # preserved for re-extraction
│
└── sessions/
    └── {user_id}/
        └── {session_id}.jsonl      # full session archive, written once at session end
                                    # never updated after write
                                    # if server crashes mid-session, no archive written
                                    # Postgres has all messages regardless
```

**JSONL archive format (Option C — full dump):**
```jsonl
{"type": "session_meta", "mode": "deep", "model": "deepseek/deepseek-chat", "total_cost_usd": 0.04, "total_tokens": 12000}
{"type": "message", "role": "user", "content": "...", "created_at": "..."}
{"type": "message", "role": "thinking", "node": "plan", "content": "...", "created_at": "..."}
{"type": "message", "role": "assistant", "content": "...", "created_at": "..."}
{"type": "paper_manifest", "papers": [{"title": "...", "doi": "...", "authors": [...], "year": 2023, "abstract": "..."}]}
{"type": "web_manifest", "sources": [{"id": "W1", "url": "...", "title": "..."}]}
```
Self-contained — readable without the app. One file per session, complete picture.

**Caveats:**
- R2 has no per-object ACL on free tier. R2 keys are unguessable UUIDs but not access-controlled. Acceptable for a two-person tool.
- R2 has no append operation. All writes are full object puts.
- R2 has no directory listing — always query by known key, never browse.
- `papers/` keys are global. Any code that has a `paper_id` can construct the key. User isolation is enforced at the Neon query layer via `user_papers`, not at R2.

## Redis key patterns

| Key | Type | TTL | Purpose |
|-----|------|-----|---------|
| `session:{session_id}:lock` | String | 10 min | Run lock — value is `run_id`. Set on run start, deleted on run end. Prevents duplicate concurrent runs if user double-submits. |
| `run:{run_id}:visited_papers` | Set | 24 hr | Within-run paper dedup. Before fetching any candidate paper, check this set first. Faster than querying Neon on every candidate during citation snowballing. |

**What is NOT in Redis:**
- Message buffer — messages write directly to Postgres from inside nodes
- Rate limit counters — handled by process-global `asyncio.Semaphore` in `lib/rate_limit.py`. Redis rate limiting only adds value with multiple instances; Render runs one. Revisit if that changes.

### `semantic_cache`

Stores embeddings of past LLM queries and their responses. On each LLM call, we first search for a semantically similar past query (cosine similarity > 0.95). Cache hit → return stored response, skip LLM call. Expected 40–60% cost reduction on repeated research topic patterns.

Embedding model: BGE-M3 (1024-dim). See SDS-10 for implementation.

| Column | Pandas dtype | Key | Notes |
|--------|-------------|-----|-------|
| `id` | `Int64` | PK | Serial |
| `query_hash` | `str` | UNIQUE | SHA-256 of `model:query` |
| `query_embedding` | `object` | | `vector(1024)` — BGE-M3 embedding of the query |
| `response` | `str` | | Cached LLM response |
| `model` | `str` | | Model that produced this response |
| `created_at` | `datetime64[ns, UTC]` | | |

HNSW index on `query_embedding`.

### `claim_relationships`

Explicit relationships between claims. Populated when the agent detects a contradiction or confirmation. V1: contradictions detected via cosine similarity range (0.6–0.85 = similar topic, potentially contradictory). V2: LLM explicitly classifies relationship type.
